Context
Why Sonar exists in an AI-first world
The same technology that generates code can be weaponized to scan it for vulnerabilities.
⚠️

The threat

Adversarial LLMs can scan any codebase in seconds to find exploitable flaws. Sonar's Mythos project proved it — AI found 200 zero-day vulnerabilities in popular open-source projects. If Sonar doesn't catch them first, attackers will.

🛡️

Sonar's answer

15 years of deterministic, fixed rules in SonarQube — rules that don't hallucinate, don't skip steps, and can't be fooled. Combined with a new AI layer, Sonar wraps the entire AI coding loop: before, during, and after code generation.

The Framework
AC/DC — Agent Centric Development Cycle
Three phases that wrap every AI coding tool — Guide the agent before it writes, Verify what it produced, Solve what it got wrong.

What is an MCP Server?
MCP (Model Context Protocol) is an open standard that lets AI agents talk to external tools — Sonar's MCP Server is the plug that connects your AI coding agent (Claude Code, Copilot, Cursor…) directly to SonarQube, so the agent can read your rules, query issues, and run scans without you doing anything manually.

How it works — 3 mechanisms
🔭
Code Navigation
GUIDE phase
Gives the agent precision tools to find exactly the code it needs — specific classes, methods, call graphs — instead of blind file exploration.
Every time an agent starts a task it "onboards" on your codebase. Each wrong file read burns tokens that cost for the whole conversation. Vortex replaces that search with focused, parser-grounded results.
📐
Constraints
GUIDE phase
Delivers a curated, task-relevant set of quality rules, architectural constraints, and dependency safety checks — so the agent doesn't violate your standards from line one.
Agents are unaware of your quality profile, architecture decisions, or licence policies. One GPL dependency choice can mean an entire PR rewrite. Vortex answers "is this dependency safe?" in a single call.
⚡
In-loop Verification
VERIFY phase
SonarQube's deterministic analysis fires inside the agent loop — each modified file verified in under 3 seconds, zero tokens consumed. Issues are corrected while context is still warm.
A final multi-file analysis at task end catches injection vulnerabilities (SQL, command, filesystem) that span several files. This does not replace CI — it eliminates 92% of what would fail it.

Common objections & answers
"You're adding stuff to the context — how does that save tokens?" ▼
Vortex saves tokens on several fronts simultaneously: Code Navigation tools output fewer tokens than native agent searches and help the agent find relevant code in fewer turns. Curated constraints prevent issues that would otherwise require costly correction loops. In-loop verification corrects problems while the agent still has codebase context loaded — no new exploration session needed.
"We already put our rules in an .md file — isn't that the same thing?" ▼
Not quite. An .md file with all SonarQube rules would force the agent to read hundreds of rules it won't use, diluting attention to the relevant ones. Vortex curates rules to the current task and quality profile — just enough signal, no noise. Architecture in an .md file also goes stale; Vortex reads it live from SonarQube, so constraints stay in sync automatically.
"We already use the Sonar MCP Server — what does Vortex add?" ▼
The standard MCP Server gives your agent the current issue list from the last CI run and quality gate status. Vortex goes much further: code navigation tools, curated constraint delivery, dependency safety lookups, and — most importantly — in-loop verification that runs before any push. The result: PRs pass quality gates at a higher rate, with lower token spend.
"Does the verification consume agent tokens?" ▼
No. The verification is the same deterministic SonarQube engine used in CI — not an AI model. It fires automatically when the agent modifies a file, delivers results in under 3 seconds, and consumes zero tokens. It also runs a deeper multi-file analysis at end of task to catch cross-file injection vulnerabilities.
"You don't catch 100% of issues — what's the point?" ▼
Catching >90% of Sonar-detectable issues before push drastically reduces failed quality gates, which translates directly to higher velocity and lower cognitive load for reviewers. True confidence in AI-generated code comes from layered verification — Vortex handles what happens before CI; Sonar in CI handles the rest. Neither replaces the other.
"We're on-premise — does this apply to us?" ▼
Not yet, but soon. Vortex is available today on SonarQube Cloud via the Sonar Agent Essentials bundle. The on-premise version ships in the next LTA release in September 2026. Worth scoping the Cloud option as a bridge, or mapping the LTA timeline into your roadmap conversation now.

The new SonarQube CLI (sonar, Beta) goes further from the terminal: sonar verify scans uncommitted changes with Agentic Analysis, sonar analyze secrets hunts for exposed credentials in any file, and sonar analyze dependency-risks runs SCA — all before a single commit.

Advanced Security
The Hunter Agent — Deep Security Layer
Above and beyond SAST: AI that reasons through your business logic like an attacker would.
Enterprise Alpha · SonarQube Cloud
SonarQube Hunter Agent (SQHA)
Standard SAST matches patterns. The Hunter Agent reasons. It uses Playbooks — structured AI reasoning scripts — to think through code logic the way a security researcher would, catching flaws that fixed rules simply cannot see.
🔓 Broken Access Control & IDOR
Can user A access user B's data by manipulating an ID or parameter?
⚙️ Business Logic Flaws
Does the application's workflow allow unintended actions or sequences?
🔑 Auth & Session Issues
Are sessions, tokens, and authentication flows handled securely end to end?
📋 Playbooks
The AI reasoning scripts that tell the agent how to hunt for each vulnerability type.
